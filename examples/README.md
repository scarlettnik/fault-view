# Исходные демонстрационные проекты

В библиотеку входят прежний Storefront и пять проектов из сети: Spring Petclinic,
Conduit / RealWorld, Fullstack Todo, Stan's Robot Shop и React + Express + MongoDB
из Docker Samples. Интерфейсы собираются из оригинальных исходников, а не заменены
новыми приложениями. Репозитории, лицензии и точные commit SHA восстановлены из
истории работы и записаны в `open-source/manifest.json`.

```bash
npm run setup             # зависимости FaultView и исходных проектов
npm run dev:all           # собрать и запустить всю опубликованную версию
```

Открыть <http://127.0.0.1:4173/>. FaultView доступен по `/app/`, Storybook по
`/storybook/`, библиотека по `/examples/`. Все шесть frontend-приложений открываются
из библиотеки. Кнопки выбора проектов также есть в FaultView на странице проектов.

Отдельные команды:

```bash
npm run setup:examples    # восстановить точные версии и установить их зависимости
npm run build:examples    # собрать шесть оригинальных frontend-проектов
npm run build            # общий артефакт site-dist для Pages и Vercel
```

Для проверки GitHub Pages:

```bash
SITE_BASE_PATH=/fault-view/ npm run build
node scripts/serve.mjs site-dist 4173 /fault-view/
```

Адрес: <http://127.0.0.1:4173/fault-view/>. Перед сборкой используется Node.js из
`.nvmrc`. На первом запуске нужны интернет, npm и tar. Повторный запуск использует
уже восстановленные версии. Загрузки не требуют GitHub-токена.

## Режим API на статическом хостинге

GitHub Pages не запускает Java, Express, Django, MongoDB или PostgreSQL. Для
автономной демонстрации к оригинальным frontend-сборкам подключён Service Worker
с локальным адаптером API. Исходные компоненты и стили сохранены; адаптация путей,
маршрутов и адресов API выполняется только в `open-source/.runtime/pages/`.

На странице каждого примера явно отмечен локальный режим. Переключатель сценария
API позволяет наблюдать поведение именно исходного интерфейса при ошибке или
восстановлении. Данные адаптера сохраняются в Cache Storage этого браузера;
их можно сбросить в DevTools → Application → Cache Storage. Учётные записи и
заказы в этом режиме демонстрационные. Настоящие пароли вводить не требуется.

Service Worker работает по HTTPS или на localhost. FaultView третьего этапа
по-прежнему строит учебные планы и симулирует результаты: адаптер не превращает
его в серверный Playwright runner и не выдаёт симуляцию за измерение внешнего сайта.

Скачанные исходники и зависимости не коммитятся: они воспроизводимо восстанавливаются
по manifest. Storefront восстановлен из его прежнего кода в `examples/storefront/`.
Backend README самого FaultView удалён; документация и лицензии исходных сторонних
репозиториев сохранены вместе с ними.
