# FaultView

Один репозиторий для лендинга, клиентского приложения и серверной части FaultView.
Лендинг уже работает; каталоги приложения и API подготовлены для добавления кода.

```text
FaultView/
├── .git/                    # Общая история всего проекта
├── .github/workflows/       # Проверки и публикация лендинга
├── .githooks/               # Необязательные локальные проверки коммита
├── apps/
│   ├── landing/             # Статический сайт, собственные npm-зависимости
│   ├── frontend/            # Будущий интерфейс приложения
│   └── backend/             # Будущий API и серверная логика
├── docs/                    # Архитектура и инструкция публикации
├── package.json             # Команды из корня, без общих зависимостей
└── LICENSE
```

## Лендинг локально

Команды выполняются из корня `FaultView/`. Нужен Node.js 22.22+ в ветке 22
или 24.8+. Для HTTP-просмотра нужен Python 3.

```sh
npm run setup:landing
npm run dev:landing
```

Откройте <http://127.0.0.1:4173>. Изменяйте файлы в `apps/landing/` и обновляйте
страницу в браузере. Также можно открыть `apps/landing/index.html` напрямую.

```sh
npm run lint:landing
npm run check:landing
npm run build:landing
```

`check:landing` проверяет форматирование, HTML, CSS и JavaScript. `build:landing`
собирает сайт в `apps/landing/dist/`; эту папку можно удалить и собрать заново.
Редактировать нужно исходники, а не `dist/`.

Все команды лендинга доступны и внутри `apps/landing/`: `npm ci`, `npm run check`,
`npm run format`, `npm run build`. Корневой `package.json` только перенаправляет команды;
устанавливать зависимости в корне не требуется.

## Добавление приложения и API

- Клиентский код добавляйте в [`apps/frontend/`](apps/frontend/README.md).
- Серверный код, миграции и серверные тесты — в [`apps/backend/`](apps/backend/README.md).
- В каждом приложении храните собственные зависимости, lock-файлы, настройки и тесты.
- Существующий код переносите без его `.git/`, зависимостей, секретов и результатов сборки.
  Вложенный `git init` не нужен: все части принадлежат одному репозиторию.

Стек frontend/backend пока не задан. Их зависимости, запуск и деплой добавляются
вместе с реализацией. Правила границ и ручных изменений описаны в
[`docs/architecture.md`](docs/architecture.md).

## Публикация

Единственный workflow — [`.github/workflows/pages.yml`](.github/workflows/pages.yml).
После слияния изменений лендинга в `main` он проверяет сайт и публикует только
`apps/landing/dist/` в GitHub Pages. Pull request запускает проверки без деплоя.
Изменения только frontend/backend не запускают этот workflow.

Настройка Pages, ручной повтор публикации и удаление старого окружения `checks`
описаны в [`docs/deployment.md`](docs/deployment.md).

## Проверка перед коммитом

При желании подключите hook один раз:

```sh
npm run hooks:install
```

Он проверяет и форматирует только подготовленные к коммиту файлы `apps/landing/`.
Для коммита только frontend/backend зависимости лендинга не нужны.
CI повторяет полную проверку лендинга независимо от локального hook.
