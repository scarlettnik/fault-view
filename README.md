# FaultView — Frontend MVP

FaultView помогает составить сценарии отказа API и посмотреть их влияние на интерфейс. Эта версия подготовлена к **третьей сдаче — 19 ноября**: React SPA сохраняет проекты в localStorage. Локальный запуск поддерживает Playwright; статическая публикация использует учебные сценарии.

В локальном режиме Playwright открывает приложение, наблюдает запросы и проверяет интерфейс при отказах API. На статическом хостинге без runner результаты остаются учебной симуляцией.

## Запуск

Нужен Node.js **24.15.0** (версия в `.nvmrc`) и npm.

```bash
nvm use                 # если установлен nvm
npm run setup
npm run dev
```

- Лендинг: <http://127.0.0.1:4173>.
- React-приложение: <http://127.0.0.1:5173>.

Bash-вариант для первого запуска:

```bash
bash scripts/start-all.sh --setup
```

Без `--setup` скрипт использует установленные зависимости, а при их отсутствии устанавливает их. `bash scripts/start-all.sh --check` запускает полную проверку и завершается. Вручную можно запустить только SPA: `npm run dev:frontend`.

Обязательных переменных окружения нет. Пример дополнительных настроек — [`.env.example`](.env.example): `FAULTVIEW_FRONTEND_PORT`, `FAULTVIEW_LANDING_PORT` для общего запуска, `VITE_BASE_PATH` для Vite, `SITE_BASE_PATH` для сборки сайта. Shell-переменные нужно экспортировать; корневой `.env` автоматически не загружается.

## Скриншоты и проверки Playwright

`npm run dev` и `npm run dev:all` запускают локальный Playwright runner на
<http://127.0.0.1:3001>. У существующего проекта нажмите **Обновить граф**, затем
**Запустить проверки**. Старые учебные прогоны сохраняются как симуляции.

В отчёте доступны скриншоты до отказа и после него, а для Recovery — также во время
сбоя; проверки контента, загрузки, JavaScript, данных и восстановления с ожидаемым
и фактическим результатом. Нажатие на снимок открывает его в полном размере.
Снимки и результаты сохраняются в `apps/backend/data/` и переживают перезапуск
runner. Удаление этой папки удалит сохранённые снимки. Прежние прогоны без снимков
нужно выполнить повторно.

По умолчанию разрешены локальные приложения на портах 4173 и 5173. Для своего
приложения задайте `FAULTVIEW_TARGET_ORIGINS` — список разрешённых origin через
запятую, включая адреса его API и ресурсов. Для отдельных процессов доступны
`npm run dev:backend` и `VITE_RUNNER_URL=http://127.0.0.1:3001 npm run dev:frontend`.
Для другого порта runner задайте `FAULTVIEW_RUNNER_PORT`; папка данных меняется
через `FAULTVIEW_DATA_DIR`. Настройки CSS-селекторов проверок — в настройках проекта.

Обычная сборка `npm run build` остаётся статической. GitHub Pages не запускает
Playwright: браузерная проверка доступна при локальном запуске с runner.

## Исходные проекты для демонстрации

В общую публикацию входят прежний Storefront и исходные frontend-приложения Spring
Petclinic, Conduit / RealWorld, Fullstack Todo, Stan's Robot Shop и React + Express +
MongoDB из Docker Samples. Скачиваются те же commit SHA, которые использовались
раньше; новые приложения вместо них не создаются. Список оригиналов и версий —
[manifest](examples/open-source/manifest.json).

```bash
npm run setup
npm run dev:all
```

Одна команда собирает и запускает весь статический сайт на
<http://127.0.0.1:4173/>: FaultView — `/app/`, шесть проектов — `/examples/`,
Storybook — `/storybook/`. Ссылки на исходные приложения есть в лендинге и на
странице проектов FaultView. На первом запуске нужны интернет и tar.

На Pages запускаются оригинальные интерфейсы с локальным адаптером API, поскольку
статический хостинг не запускает их серверы и БД. Действия в интерфейсах сохраняются
в этом браузере. Переключатель сценария API показывает реакцию исходного приложения
на отказ; учебные результаты самого FaultView не являются измерениями этих страниц.
Устройство сборки и отдельные команды описаны в [инструкции примеров](examples/README.md).

## Стек и архитектура

- **React + TypeScript**, функциональные компоненты и хуки, строгая типизация.
- **Redux Toolkit:** `workspace` хранит проекты, графы, планы и результаты; `operations` — состояние асинхронных операций и ошибки.
- **createAsyncThunk:** `discoverProject`, `prepareLocalPlan`, `executePlan`, `cancelOperation` выполняют локальные операции с состояниями pending / fulfilled / rejected. Подмена на реальные HTTP-запросы запланирована на следующий этап.
- Типизированные хуки dispatch / selector и отдельные [селекторы](apps/frontend/src/store/selectors.ts), включая мемоизированный селектор количества проектов.
- **React Router / HashRouter:** список проектов, создание, обзор, настройки, зависимости, планы, история, результат прогона, «О проекте». HashRouter сохраняет переходы и обновление страницы на статическом хостинге.
- **Zod + YAML:** валидация формы, структуры хранилища и поддерживаемой части OpenAPI. Внешние `$ref` отклоняются; загрузка удалённых схем не выполняется. Поддержка OpenAPI намеренно ограничена операциями и локальными переходами `operationId` / `operationRef`, а не всей спецификацией.
- **Vite**, CSS, локальные шрифты, адаптивная навигация, семантические элементы и управление с клавиатуры.

```text
apps/landing/                 HTML, CSS, JS — второй этап
apps/frontend/src/
  components/                 формы, граф, отчёт, общие компоненты
  pages/                      страницы React Router
  store/                      Redux-слайсы, thunk-операции, селекторы, сохранение
  core/                       модель, OpenAPI, каскады, локальная симуляция
  hooks/                      подготовка локального плана
apps/frontend/.storybook/     конфигурация Storybook
apps/frontend/e2e/            браузерные сценарии
apps/frontend/visual/         визуальные тесты и эталоны
scripts/                      запуск, сборка сайта, установка Git hook
.github/workflows/pages.yml   проверки PR и публикация после проверки main
```

## Модель данных

Основная сущность — **Project**: название, описание, адрес, исходный OpenAPI и лимит страниц. Проект содержит историю построений **Job / Graph**, сохранённые **SavedPlan** и прогоны **TestRun**. Граф связывает страницы с операциями API и содержит направленные OpenAPI Links. План содержит выбранный узел, направление, исключения и профили; прогон — прогресс и результаты отдельных комбинаций.

Данные сохраняются синхронно при изменении Redux-состояния в `localStorage["faultview.workspace.v2"]`. Сохраняются до 30 проектов, 20 графов, 20 планов и 5 последних прогонов на проект. Предыдущий ключ хранилища не используется. Повреждённые данные не перезаписываются автоматически; при ошибке или переполнении хранилища интерфейс показывает сообщение. История привязана к браузеру и origin, поэтому localhost, Pages и Vercel имеют разные данные. Подготовка серверной базы на этом этапе не требуется.

При повреждении данных сначала сохраните исходное значение ключа через DevTools → Application → Local Storage. После резервного копирования можно удалить только `faultview.workspace.v2` и обновить страницу. При переполнении выгрузите нужные проекты через «Экспорт JSON» и удалите лишние. Импорт резервных JSON в этой версии не реализован.

## Содержательная сложная функция

**Каскадное планирование по направленному графу.** От страницы алгоритм проходит её операции и объявленные переходы вперёд; от API идёт назад и находит затронутые страницы. Обход завершается при циклах, исключения учитываются, повторяющиеся профили не дублируют комбинации. Объявленная связь отделена от локального сценария: её отсутствие даёт SKIP, а не ложный PASS. Планировщик встроен в основной путь «граф → план → прогон».

Профили: Healthy, Latency, HTTP 500, HTTP 503, Timeout, Network error и Recovery. Вердикты определены локальными сценариями. Это демонстрация frontend-поведения; настоящая проверка устойчивости внешнего приложения появится на четвёртом этапе. При необходимости соответствие сложной функции высокой оценке следует согласовать с преподавателем.

## Проверки

```bash
npm run check                      # формат, все линтеры, TypeScript, unit/компоненты
npm --prefix apps/frontend exec -- playwright install chromium
npm run verify                     # check + сборка сайта + Storybook + E2E + visual
```

Отдельные команды:

| Команда                      | Что проверяет                                                                                            |
| ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `npm test`                   | Vitest: Redux-редьюсеры, асинхронные состояния, OpenAPI, граф, планирование, формы и Button              |
| `npm run typecheck`          | Строгая проверка TypeScript, включая тесты и Storybook                                                   |
| `npm run lint`               | ESLint frontend и Node-скриптов; HTML, CSS, JS лендинга                                                  |
| `npm run format:check`       | Prettier без изменения файлов                                                                            |
| `npm run format`             | Форматирование исходников и документации                                                                 |
| `npm run test:site`          | Собранный лендинг → SPA, загрузка ресурсов под hosting prefix и прямое обновление маршрута               |
| `npm run test:e2e`           | Playwright: CRUD с перезагрузкой, граф → план → прогон → история, мобильный вид, отсутствие API-запросов |
| `npm run storybook`          | Storybook на <http://localhost:6006>                                                                     |
| `npm run build:storybook`    | Статическая сборка историй                                                                               |
| `npm run test:visual`        | Сравнение 7 скриншотов 4 компонентов с сохранёнными эталонами; сначала собрать Storybook                 |
| `npm run test:visual:update` | Обновление эталонов после ручной проверки намеренных изменений                                           |
| `npm run precommit`          | Та же быстрая проверка, что `check`; без изменения и staging файлов                                      |

Storybook содержит Button (обычное, вторичное, disabled, loading), StatusBadge, Notice и ProjectForm. Эталоны созданы для Linux и комплектного Chromium Playwright. Для воспроизводимых сравнений на другой ОС используйте Ubuntu 24.04 или CI; не перезаписывайте Linux-эталоны ради отличий рендеринга шрифтов.

Общая сборка `npm run build` включает лендинг, SPA и Storybook. После merge в `main` и успешного workflow `Quality and Pages` они публикуются по адресам:

- Лендинг: <https://scarlettnik.github.io/fault-view/>.
- Приложение: <https://scarlettnik.github.io/fault-view/app/>.
- Storybook: <https://scarlettnik.github.io/fault-view/storybook/>.

В Settings → Pages источником публикации должен быть выбран GitHub Actions. Если environment `github-pages` требует подтверждения, публикация будет ждать его. Проверка `test:site` открывает собранный лендинг, переходит в SPA, проверяет перезагрузку маршрута и загрузку компонента Storybook с префиксом хостинга.

API-интеграционные тесты и E2E с настоящим сервером относятся к четвёртой сдаче. Здесь E2E проверяет UI и реальное localStorage, а также отсутствие HTTP API.

## Pre-commit и pull request

`npm run setup` устанавливает `.githooks/pre-commit` в локальном Git checkout. Повторная установка: `npm run hooks:install`. Hook не создаёт коммиты. Проверить его вручную без коммита: `sh .githooks/pre-commit`.

Workflow **Quality and Pages** запускает `npm run verify` на push и pull request. Обязательность этого результата для merge нужно включить в GitHub branch protection/ruleset: выбрать check **Verify frontend MVP** и запретить обход правила. Сам файл workflow не включает настройки защиты репозитория.

Публикация Pages разрешена только после успешного quality job для `main`. В fork PR публикация не выполняется. E2E и visual вынесены из pre-commit в полную проверку, чтобы каждый коммит не требовал браузерной сборки. CI дополнительно устанавливает системные зависимости Chromium; локальная команда не меняет систему.
